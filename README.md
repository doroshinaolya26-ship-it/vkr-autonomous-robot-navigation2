# vkr-autonomous-robot-navigation2

Разработка алгоритма построения маршрута и навигации автономного мобильного робота 2.

## Запуск основного проекта

Основной проект по-прежнему запускается из корня репозитория:

```bash
python main.py
```

## Интеграция с CoppeliaSim

Интеграция с CoppeliaSim добавлена как отдельный демонстрационный слой и не изменяет логику основного алгоритма навигации. Она предназначена для визуализации мобильного робота, его сенсорных компонентов локального восприятия, статических препятствий, стартовой и целевой точек, а также движения по маршруту, рассчитанному алгоритмом A*.

### Установка CoppeliaSim

1. Скачайте и установите CoppeliaSim с официального сайта проекта.
2. Убедитесь, что в установленной версии доступен ZeroMQ Remote API.
3. Если Python не находит модуль `zmqRemoteApi`, добавьте путь к API в `PYTHONPATH` или задайте переменную окружения `COPPELIASIM_ROOT`, указывающую на каталог установки CoppeliaSim.

### Подготовка сцены

Готового бинарного файла сцены `.ttt`/`.ttm` в репозитории нет: такие файлы обычно сохраняются из установленного CoppeliaSim. Поэтому добавлены два воспроизводимых варианта подготовки сцены:

```text
coppeliasim/create_demo_scene.lua      # Lua-скрипт автоматической генерации сцены
coppeliasim/CREATE_SCENE_SCRIPT.md    # инструкция по запуску Lua-скрипта
coppeliasim/SCENE_SETUP.md            # ручная инструкция, если скрипт нужно адаптировать
```

Рекомендуемый путь: открыть CoppeliaSim, выполнить `coppeliasim/create_demo_scene.lua`, сохранить полученную сцену как `.ttt`, затем запустить Python-контроллер. Сцена должна содержать объект мобильного робота с именем `robot`, колесную базу, левое и правое приводные колеса, корпус, лидар или дальномерный сенсор, датчики расстояния, IMU, энкодеры колес, контактный сенсор, локальную карту/occupancy grid, статические препятствия, стартовую и целевую точки.

### Запуск Python-контроллера

1. Откройте подготовленную сцену в CoppeliaSim.
2. Запустите симуляцию кнопкой `Start simulation`.
3. Из корня репозитория выполните:

```bash
python coppeliasim/coppelia_controller.py
```

Контроллер пытается подключиться к CoppeliaSim через `zmqRemoteApi`, получить объект `/robot`, загрузить маршрут из `results/astar_path.txt` при наличии и пошагово переместить робота по точкам. Если файл маршрута отсутствует, используется небольшой демонстрационный маршрут.

### Fallback-режим

Если CoppeliaSim, `zmqRemoteApi` или объект `robot` недоступны, контроллер не завершается с непонятной ошибкой. Вместо этого он запускает fallback-режим, выводит причину проблемы и сохраняет демонстрационные метрики без управления 3D-сценой.

Принудительный запуск fallback-режима:

```bash
python coppeliasim/coppelia_controller.py --fallback
```

### Результаты симуляции

После запуска контроллера формируется файл:

```text
results/coppelia_metrics.txt
```

В нем сохраняются режим запуска, число достигнутых точек маршрута, длина траектории, финальная позиция и перечень сенсорных компонентов мобильного робота.

Дополнительно в репозитории есть пример описания компонентного состава:

```text
results/coppeliasim_component_specification_example.txt
```

### Материалы для защиты ВКР

Для пояснительной записки и презентации рекомендуется использовать следующие файлы:

- `coppeliasim/SCENE_SETUP.md` — пошаговая инструкция по созданию сцены CoppeliaSim;
- `docs/ROBOT_COMPONENTS_SPECIFICATION.md` — академическая спецификация сенсорных компонентов мобильного робота;
- `docs/COPPELIASIM_SCREENSHOT_GUIDE.md` — перечень скриншотов, которые нужно подготовить для ВКР;
- `results/coppeliasim_component_specification_example.txt` — краткий пример компонентного состава и данных сенсоров;
- `results/coppelia_metrics.txt` — метрики движения после запуска контроллера.
